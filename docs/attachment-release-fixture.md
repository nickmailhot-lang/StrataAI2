# Explicit local attachment release fixture

The sanctioned private local object-storage adapter can now be selected by an explicit `STRATAAI_ATTACHMENT_TEST_LOCAL_ROOT` absolute path only when the actual host environment and `ASPNETCORE_ENVIRONMENT` are IntegrationTest. API/Worker startup supplies the real host environment separately; a configuration value cannot override that proof. If `DOTNET_ENVIRONMENT` is supplied, it must also be IntegrationTest. Storage must be explicitly enabled, and the application still uses its Production runtime descriptor and restricted PostgreSQL stores. Demo activation remains forbidden. This is a test capability, never fallback after S3 failure.

Without that setting, enabled runtime storage still requires the canonical managed AWS bucket, owner and region, regional HTTPS endpoint, SDK credentials and current private bucket checks. No custom endpoint or new Production provider was added. Startup resolves the selected storage adapter behind fixed diagnostic refusal. Local fixture readiness rechecks private directory ownership, permissions and links as well as PostgreSQL and, on the Worker, its existing local scanner socket.

Upload policies, source admission, durable scan jobs, the separate Worker's ClamAV protocol, isolated image decoder, committed preview publication, original receipt recovery and integrity-checked delivery are unchanged. The same release images can use a disposable private directory and scanner protocol fixture to exercise the entire pipeline. Such a run will prove application pipeline behavior with explicitly declared providers; it will not prove managed AWS availability or a real malware engine if its scanner replies are simulated.

Domain configuration boundary tests and mandatory exact-image refusal cases reject Production/Development activation, conflicting host environments and relative roots. Compilation/syntax checks are local evidence only; Linux execution remains pending. The disposable directory/scanner fixture and actual pipeline scenario are the next required work. Do not count this registration foundation as completed release acceptance or close PRD-04/PRD-14/ARCH-07.
