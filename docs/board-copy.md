# Independent Board copies

PRD-04 BOARD-FR-006/007 has an authenticated `POST /boards/{boardId}/copy` producer accepting `name` and the reviewed Board `version`. It creates a private active Board in the source Organization, with a normalized new name, source description and approved built-in color background. Copying requires current source edit access and active Organization membership/create admission. Archived/deleted/inaccessible sources use Board-not-found before protected validation. A stale first submission conflicts. Image backgrounds await the stored-image admission work and are currently rejected, rather than extending an unverified image capability through copying.

The default content policy copies every non-deleted List and Card, including archived children, in the same relative rank order. It creates all-new identities, creation/update clocks and revision 1; copied archived children receive their own archive clock. All active label definitions are independent, including unused and duplicate-looking labels, and shared associations stay shared across the copied Cards. Card titles, descriptions and UTC dates are retained. Non-deleted checklists/items are copied without UI pagination caps; due completion and checklist completion are reset for new work. Deleted children are omitted. Source state is unchanged.

Source memberships, Card assignments, personal stars/watches/reminders, comments/activity, attachments/covers and historical completion attribution are excluded. The creator receives the new Board's required administrator grant; this is fresh admission, not a copied roster. The new Board uses normal default date presentation policy. Attachment copying and stored-image Board backgrounds remain distinct unfinished contracts.

The command holds fresh source Board/account/Organization admission through its owning tenant transaction. PostgreSQL uses composite-scope mappings and bulk inserts; demo storage uses equivalent dictionary mappings covered by transaction rollback. Parent/child records, route triggers, fresh administrator grant, BOARD_CREATED/BOARD_COPIED audit/envelopes and durable delivery jobs, and the actor-scoped receipt commit together. No source history is copied. Stable sorted Board gates re-admit both the original source and retained destination before recovering a historical acknowledgment. The original request/key recovers the original result after a source rename without creating another Board; changed intent conflicts. Source archive or destination loss withdraws receipt disclosure.

Source host tests cover private identity/content/checklist isolation beyond the 50-row page size, label independence, creator-only admission, unchanged source, original receipt recovery, changed intent/stale revision, viewer/anonymous denial, validation and archived-source replay denial. Full solution compilation passes with warnings as errors. Local Windows application control prevents API test execution; Linux source CI is required.

The mandatory immutable-image fixture seeds 200 Lists and 5,000 Cards (including archived children), two distinct shared labels and checklists beyond page size. It exercises the restricted API login, withdraws late checklist insertion capability, checks fixed storage refusal and unchanged records/effects/receipts/routes, restores capability, retries the same key, and verifies full copied counts, 10,000 label associations, fresh checklist work, events, repeat identity and archived-source denial. Script syntax passes; executed PostgreSQL proof is pending CI. This is capacity correctness coverage, not proof of latency targets or 100,000 archived Cards per Organization.

Fixed operator telemetry uses `board_copy` without source/copied names or identifiers. The existing authorized Board activity presentation recognizes BOARD_COPIED, and the existing separate Worker publishes the new Board's durable events. MUI review/recovery/navigation, native/mobile/a11y scenarios, concurrent/revocation/late-publication variants, background-image compatibility and measured performance remain unfinished.
