# UX-005: Standardized Forms, Tables, Dialogs, and Feedback

Status: Organization settings field-feedback/header/action slice implemented under PRD-03; current validation and broader forms/tables/dialogs acceptance remain separate.

## Scope and ownership

Incremental UX delivery workstream. Canonical business/security requirements remain in PRD-02–18; PRD-21/22/24; domain PRDs. This PRD adds implementation and acceptance detail; it does not replace or close those tickets. No new database schema, API contract, tenant permission or parallel frontend framework is authorized by this PRD.

## Dependencies

UX-003 tokens/compositions; UX-001 page slots. Preserve WorkMutationIntent, canonical reads, versions, problem references and original-command retries.

## User journeys

Admin reviews a membership change, cancels or confirms, recovers a lost response, and reads the canonical result; Contributor corrects a field without losing a draft; Viewer pages a read-only directory.

## Implementation tasks

- [ ] UX-005-T-01: Audit current controls, directories, dialogs and feedback and select existing working patterns as reference.
- [ ] UX-005-T-02: Standardize field labels/help/errors, pending state, primary action placement, empty/error directories and accessible pagination.
- [ ] UX-005-T-03: Preserve explicit destructive consent, current-version admission, conflict draft review, original-key recovery and cancel/Escape semantics.
- [ ] UX-005-T-04: Make wide tables usable via local scrolling or approved mobile row composition while retaining all required data/actions.

## Current incremental slice

Organization settings is the first migrated form: shared PageHeader/ActionRow, linked input errors and focus for name validation and the existing server logo refusal. Existing actor/version/key-bound save, draft comparison, uncertain-original recovery and live withdrawal remain in the feature. No form framework or generalized mutation wrapper is introduced. Broad task checkboxes are not completed by one migrated form; current evidence is in the single delivery report.

## Acceptance criteria

- UX-005-AC-01: Errors identify the relevant field/action; actionable failure includes safe support reference and explicit retry when permitted.
- UX-005-AC-02: Validation/network/conflict states preserve recoverable drafts; original commands retain identity and cannot become accidental new writes.
- UX-005-AC-03: Dialogs trap/restore focus, retire unsubmitted consent on cancel/role loss, and never auto-replay destructive actions.
- UX-005-AC-04: Tables expose headings, order, pagination/loading and row action names on narrow screens; loading is distinct from no records.

## Automated tests

- UX-005-TC-01: Unit: validate/cancel/submit/pending, original-key retry, newer-version conflict, protected-generation withdrawal and directory paging.
- UX-005-TC-02: Integration: actual persistence, authorization, idempotency and no duplicate writes across lost responses and reconnects.
- UX-005-TC-03: Playwright: keyboard dialog/form/paging with focus restoration and preserved drafts; responsive/Axe checks for actual migrated feature consumers.

## Delivery and acceptance

Use the [shared feature UX acceptance addendum](feature-acceptance.md) and [single delivery report](delivery-report.md). Record implemented, tested and accepted separately. Tests above are required coverage, not a claim of execution. Existing feature delivery can proceed where it does not mutate shared shell/navigation/theme files. One owner edits those files in each integration window; feature owners consume approved slots. Use a small PR per migration; use a reversible feature flag before any migration that would interrupt an existing workflow. This additive specification does not flag or replace working business functionality.

Acceptance requires all applicable quality gates, current revision evidence, documented failure evaluation and role-specific end-to-end review. UX completion cannot raise functional completion or MVP readiness by itself.
