# UX-007: Workflow Discoverability and Contextual Guidance

Status: Specified; existing onboarding and relationship PRDs remain owners.

## Scope and ownership

Incremental UX delivery workstream. Canonical business/security requirements remain in PRD-01/16/18/54–60/80; each owning domain PRD. This PRD adds implementation and acceptance detail; it does not replace or close those tickets. No new database schema, API contract, tenant permission or parallel frontend framework is authorized by this PRD.

## Dependencies

UX-001/002 entry points; UX-003/005 presentation. PRD-60 owns onboarding/invitation behavior and PRD-57 owns record relationships.

## User journeys

New internal member moves from invitation to first permitted Board action; Viewer finds an empty-state explanation; Admin follows a source record to a related workflow and returns.

## Implementation tasks

- [ ] UX-007-T-01: For each feature, document entry point, role, context, next permitted action and return route in the backlog matrix.
- [ ] UX-007-T-02: Add concise in-context help to actual empty/error/permission/first-use states without blocking expert tasks.
- [ ] UX-007-T-03: Use existing related-record/search/notification links; do not create a second onboarding system, help route or unsupported tour.
- [ ] UX-007-T-04: Test first-use, no-data, denied, interrupted and return journeys with representative users.

## Acceptance criteria

- UX-007-AC-01: Every new/active feature has a discoverable authorized entry, descriptive action and documented role workflow.
- UX-007-AC-02: Empty/denied states explain safe next steps without revealing inaccessible entities.
- UX-007-AC-03: Help preserves focus, drafts and route context; guidance never initiates writes or auto-accepts invitations.
- UX-007-AC-04: Role-appropriate end-to-end discovery/return is tested; user review records task success and unresolved confusion.

## Automated tests

- UX-007-TC-01: Unit: guidance visibility by state and role, link destinations and non-disclosure.
- UX-007-TC-02: Integration: invitation discovery/acceptance and relationship links retain current permission/receipt rules.
- UX-007-TC-03: Playwright: first-use and returning-user journeys, keyboard help open/dismiss, interruption recovery, mobile/Axe and role-loss negatives.

## Delivery and acceptance

Use the [shared feature UX acceptance addendum](feature-acceptance.md) and [single delivery report](delivery-report.md). Record implemented, tested and accepted separately. Tests above are required coverage, not a claim of execution. Existing feature delivery can proceed where it does not mutate shared shell/navigation/theme files. One owner edits those files in each integration window; feature owners consume approved slots. Use a small PR per migration; use a reversible feature flag before any migration that would interrupt an existing workflow. This additive specification does not flag or replace working business functionality.

Acceptance requires all applicable quality gates, current revision evidence, documented failure evaluation and role-specific end-to-end review. UX completion cannot raise functional completion or MVP readiness by itself.
