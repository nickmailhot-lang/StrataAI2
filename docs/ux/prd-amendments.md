# Strata usability amendments and delivery contract

Date: 2026-10-17. Read with [current-state audit](current-state.md). These additive requirements preserve every existing PRD ID, functional requirement, permission, audit and completion gate. Parent PRDs remain open until all required children pass their own gates. No whole redesign dependency is added to unrelated PRDs.

## Shared interaction contract

Use React/MUI and existing apiFetch, Problem, mutation intent, surface admission and feature state boundaries. Theme tokens: primary #0f4c81, secondary #3d6f8e, canvas #f5f7fa, paper #fff; MUI spacing unit 8px, sidebar 248px, content min-width 0, phone breakpoint below 600px, desktop drawer breakpoint 900px, panel width min(720px, viewport), body 1rem, metadata 0.875rem, 10px surface radius. Fields have persistent labels; controls use visible focus. Important states combine text and color. Necessary horizontal scrolling belongs to BoardWindow, never the page. Standard MUI dialogs/menus preserve keyboard behavior and focus restoration. No new component framework.

Collapsed Card contract: title first, wrapping/clamped to three lines with full accessible name and full title in detail; affected units next when supported (first two plus “+N units”; common property is explicit scope, never a fake unit). Show assignee names/initials from authorized version-bound previews; explicit Unassigned only for a valid zero-member preview, unavailable data must not imply unassigned. Due date shows day/month/year in board/viewer timezone, with existing textual overdue/complete state. Missing date says No due date. Priority only when backed by PRD-34 data. Count indicators only from bounded authorized aggregate previews; no per-card child fetches. Do not repeat List status on each card. Descriptions, email bodies, vote details and histories stay in detail. Units/priority/counts not present in the API remain tracked gaps, not invented placeholder data.

Detail hierarchy: Summary and core editing; Description, checklist and attachments; Related records when backed by services; Discussion and Activity labeled separately. Core save and close stay visible; secondary operations have a labeled disclosure. Desktop right panel and full-screen phone presentation share the stable existing Card URL. Keep the board mounted, its filter result, horizontal/vertical scroll and origin focus. Back behaves as close when board history exists. Dirty core edits require explicit discard before closing or navigating, and browser unload protection. No client draft bypasses permission revocation. Failed saves keep input and original retry identity; pending/uncertain commands retain existing recovery controls. Do not unmount recovery-owning components merely to hide them.

Every slice includes loading announcements, useful empty action, fixed safe error with retry, saved/saving feedback, current permission state, keyboard operation, visible focus, responsive overflow and focus recovery. Consequential operations retain existing review/confirmation; undo is offered only where server lifecycle supports it. No silent optimistic archival, vote or merge. Existing API authorization and tenant/portal boundaries remain authoritative.
