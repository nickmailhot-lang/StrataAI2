# UX-003: Shared Design System and Component Library

Status: Specified; existing appTheme retained.

## Scope and ownership

Incremental UX delivery workstream. Canonical business/security requirements remain in PRD-01/19/23/25; ARCH-02. This PRD adds implementation and acceptance detail; it does not replace or close those tickets. No new database schema, API contract, tenant permission or parallel frontend framework is authorized by this PRD.

## Dependencies

UX-001 shell inventory; current appTheme, MUI, Emotion and existing controls. UX-002 supplies naming, not a replacement framework.

## User journeys

Contributor recognizes the same primary action, status and error pattern across Organization, Board and Card; keyboard user sees consistent focus and reads status independent of color.

## Implementation tasks

- [ ] UX-003-T-01: Catalog existing typography, spacing, colors, focus, surfaces, breakpoints and control variants; identify actual duplication before extraction.
- [ ] UX-003-T-02: Document semantic tokens through current appTheme and MUI overrides; reuse current components before creating thin shared compositions.
- [ ] UX-003-T-03: Create representative component fixtures for loading/empty/error/disabled/focus/long-content states and sanctioned page/action slots.
- [ ] UX-003-T-04: Migrate one consumer at a time; compare production CSS/CSP behavior and preserve existing semantics and accessible names.

## Acceptance criteria

- UX-003-AC-01: New/active feature UI uses MUI and documented tokens/compositions; no parallel CSS framework or standalone layout/navigation.
- UX-003-AC-02: Shared primitives preserve native semantics, visible focus, contrast, labels, loading and non-color status.
- UX-003-AC-03: Token or component updates include affected-consumer regression evidence and visual approval; no blanket component rewrite.
- UX-003-AC-04: Long content and supported viewport/text-zoom states remain readable; no hidden critical controls or security-state animation regressions.

## Automated tests

- UX-003-TC-01: Unit: appTheme.test.tsx plus semantic/interaction tests of extracted components and at least two actual consumers.
- UX-003-TC-02: Playwright/Axe: representative shell, forms, tables and dialogs at mobile/tablet/desktop with production CSP.
- UX-003-TC-03: Visual: deterministic approved fixtures, focus/disabled/error contrasts and long content under UX-008; no automatic baseline replacement.

## Delivery and acceptance

Use the [shared feature UX acceptance addendum](feature-acceptance.md) and [single delivery report](delivery-report.md). Record implemented, tested and accepted separately. Tests above are required coverage, not a claim of execution. Existing feature delivery can proceed where it does not mutate shared shell/navigation/theme files. One owner edits those files in each integration window; feature owners consume approved slots. Use a small PR per migration; use a reversible feature flag before any migration that would interrupt an existing workflow. This additive specification does not flag or replace working business functionality.

Acceptance requires all applicable quality gates, current revision evidence, documented failure evaluation and role-specific end-to-end review. UX completion cannot raise functional completion or MVP readiness by itself.
