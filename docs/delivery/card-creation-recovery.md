# Original-account Card creation recovery

Independent slice `PRD-08-VS-04` refines the existing creation capability without moving or restarting `PRD-08-VS-01`. Original PRD-08 obligations and linked source tests remain open. The existing Card title/rank/editor, authorization, lifecycle, events, original-key receipt store and canonical Board/Card routes are reused.

Both genuine desktop/mobile counterfactuals reproduced a duplicate: a contributor's first Card creation committed but its reply was lost; the browser cookie was replaced with its independently authorized Organization owner; the same request key/body returned another 201 with another ID. The canonical List held two Cards. Their separate actor receipt namespaces were functioning correctly; the stale browser command did not carry its original identity. Initial fixture wording and intermediate UI feedback failures are retained separately from this demonstrated defect.

The focused repair confirms the authenticated profile in a bounded read when the user explicitly opens a Card form. The form stays unavailable while identity is uncertain and announces its access check. No new polling or shared shell/context mechanism is introduced. A failed read displays safe existing feedback and permits explicit entry retry; route departure, definitive Board refusal or loss of permission/active List cancels admission. The confirmed actor stays in that form through explicit unchanged retries. The existing `WorkMutationIntent` and body remain unchanged; the creation URL includes optional `expectedActorId`.

The server compares that optional identity with the authenticated principal before Card mutation. A mismatch returns the existing `session_unavailable` response; the hint grants no permission. Legacy callers may omit it, while current service authorization, active-parent checks and receipt validation remain authoritative. There are no database, event, body schema or dependency changes. List creation and independent commands remain separate audits.

UXA-01–08 apply through existing MUI controls and Board/List entry, bounded loading/error/denial, explicit original-key recovery, canonical Card/reload/return, 320/390/768/1280px, 200% tablet text, keyboard/focus and applicable Axe. Developer visual inspection is recorded separately from automated checks and full product/release acceptance. Tests, exact source/results, historical failures and pending integration are held in the machine-readable ledger. No PRD or slice becomes Done from implementation alone.

Material assumption: confirming identity at explicit form entry binds that new command. A cookie change after entry never refreshes the old form's actor or automatically executes it as the replacement account. A new independently opened and authorized form may start a new command. The original-key algorithm and original server receipt namespaces are preserved.
