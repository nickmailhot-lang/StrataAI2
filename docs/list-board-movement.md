# List movement between Boards (PRD-07)

[PRD-07](https://github.com/nickmailhot-lang/StrataAI2/issues/8) includes moving a List to another authorized Board. Existing List reordering and copying do not satisfy that requirement. The implementation is in progress; this document preserves the full movement scope while recording the first Domain increment.

## Canonical Domain transition

`BoardList.MoveToBoard` changes the parent Board and normalized rank within the List's existing Organization. Identity, Organization, name and creation history remain unchanged; one successful transition advances its version and update timestamp once. Empty destinations, different/empty Organizations, empty ranks and backwards timestamps are rejected before changing the parent or rank. Caller-supplied destination context is not authorization: the Application service must resolve and admit both real Board scopes before invoking a transition.

Nine focused Domain cases cover identity/history preservation, subsequent movement and complete unchanged state for invalid scope, destination, rank and time. Together with the four existing canonical hierarchy cases, **13/13 pass**, zero skipped or failed. A fresh solution build succeeds with no warnings/errors; all 213 immutable CI coverage guards pass. These checks establish the entity transition, not a working transfer endpoint or full PRD acceptance.

## Domain rejection atomicity

The graph review found that `Card.Move` assigned parent IDs before rank validation, and canonical rename/reorder methods assigned fields before rejecting backwards timestamps. A rejected operation could therefore leave a partially changed in-memory entity. These methods now normalize input and complete clock validation before assigning their fields. Accepted values, normalization and successful version/time advancement remain unchanged.

Before the repair, nine of ten targeted rejection cases fail complete serialized-state comparisons; the new List-to-Board transition already passes its corresponding guard. After the repair, all rejection cases and seven successful mutation paths pass. Combined with List movement and canonical hierarchy coverage, **30/30 pass**, zero failed/skipped. The final solution build has no warnings/errors and all 217 CI coverage guards pass. This establishes Domain validation behavior; it does not prove transfer persistence, HTTP authorization or the whole graph transaction. The complete List-transfer implementation below remains necessary, with estimated PRD-07 work remaining unchanged at **35%**.

Ordinary writes still reject parent mismatches immediately. The future owning transfer transaction can explicitly defer this one constraint while updating the List and its contained Cards; an inconsistent final graph still cannot commit. The runtime schema check now requires migration 147 before accepting Production traffic. Apply the migration before starting the new hosts, as with the existing release procedure.

## Shared label reference planning

`CardLabelTransferPlan` captures source definitions and Card associations before mutation. Multiple Cards sharing a source label retain one planned definition and every distinct association. It rejects mismatched Organization/Board definitions, unknown Cards or labels, and conflicting versions of a definition. Deleted and unreferenced definitions do not become destination labels; source ordering uses ordinal rank. The plan owns an immutable snapshot and grants no destination authorization. Both existing single-Card stores now use this shared planning rule before creating destination labels.

All **14 focused planner cases pass**, including 100,000 supplied Card associations sharing one definition. This is an in-memory reference-planning check, not a database throughput or complete List-transfer test. The fresh solution build has zero warnings/errors, and all 217 CI coverage guards pass. Existing movement/label HTTP checks on Windows pass **14 cases**, with one private-file case explicitly skipped because private staging requires Linux. Restricted PostgreSQL and retained-image Linux/browser acceptance remain required; no release certification follows from these local checks. Estimated PRD-07 work remaining stays **35%**.

## Remaining implementation

Migration `148_configuration_historical_list_identity` removes a permanent pin caused by immutable configuration history: a former intake List could not change Boards even after the owning configuration selected a different intake List. History now references the stable List within its tenant and retains the original Board attribution separately. Current configuration keeps its composite Board/List constraint. Its existing live-parent/source guard and exact-record history journal remain unchanged; current intake movement and fabricated configuration/history sources still fail. Historical records, receipts, audit and events are not rewritten, and historical references grant no current destination access. Hosts now require migration 148, so upgrade the database before starting them.

The mandatory real PostgreSQL parent suite seeds two genuine configuration revisions through the current-source/history/receipt guards before upgrading. The old historical constraint refuses former-intake movement. After upgrade, authenticated restricted-runtime movement succeeds for the former intake List, current-intake movement fails with a complete unchanged graph, and history retains its original Board. Complete seeded graph and configuration/current/history/receipt/audit/event hashes are unchanged by the upgrade. Forged live-parent changes, mismatched history sources, runtime history updates and unscoped/other-tenant history reads remain refused or withdrawn. Both comprehensive database cases pass, as does the restricted-role provisioning regression. Forty focused Domain/planner cases, 219 CI/startup guards and a zero-warning/error build pass. Owned fixtures remove containers and anonymous volumes. These are database prerequisite checks; the complete transfer, HTTP/MUI flow and immutable-image acceptance below remain required. Estimates remain PRD-07 **35%**, PRD-27 **24%**.
