# Command actor sessions

Work, organization and invitation mutations revalidate the actor after acquiring their command permission scopes. HTTP authentication records only the hash of the authenticated session in a request-local host context. Application verification binds that context to the command actor, checks the active account and configured email policy, then checks the original unexpired/unrevoked session. Failed admission returns `session_unavailable` HTTP 401 without protected content. Trusted in-process service calls have no HTTP session context but still require an active account and domain permissions; this is not an anonymous HTTP bypass.

PostgreSQL verification borrows the root transaction. Account reads lock the user for share before the session row is locked for share, matching deactivation's user-before-session ordering. Session checks also use database wall time, including after waits. Work replay admission repeats the check after the unique retry claim wait. Locks remain held until commit/rollback: a revocation already committed during a scope wait rejects admission, while a revocation racing an admitted command must wait for that command's commit. Demo checks are process-local and do not prove cross-process atomicity.

Required restricted-database fixtures observe real lock waits before committing session logout, expiry or account deactivation. They compare cards/list/board/audit/event/job/replay state, including a previously successful retry whose cached result must not be disclosed to a revoked session. The reverse-order audit gate verifies both membership revocation and session revocation wait for an admitted card edit. Organization creation, metadata edits and invitation creation also reject logout during their admission waits without state/audit changes. Invitation recipient deactivation at this common admission boundary now yields the same masked 401; invalid issuer grants remain masked invitation failures.

This increment adds no migration or external service and preserves the existing architecture. It does not declare every read path/session transition, identity operation, UI flow, durable retry rule, lifecycle action or ticket acceptance criterion complete. The separate Worker does not acquire a fabricated HTTP actor context.
