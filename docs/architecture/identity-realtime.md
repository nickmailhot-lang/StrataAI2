# Identity realtime recovery

The profile opens the existing SignalR SDK over `/me/live` after its first authenticated `/me/sync` snapshot. A connection may watch only its authenticated account, with one active subscription; no user/Organization/Board ID is accepted. Strict configured-origin checks cover negotiation and websocket upgrade. The route requires authentication, shares existing buffer/message bounds and uses same-origin cookies without query-string credentials. Development and release proxies forward websocket upgrade correctly.

The API revalidates the opaque session before each bounded identity replay read and again before sending its result. Logout, expiry, reset or deactivation therefore ends access rather than preserving handshake authority. Each read enters the existing global identity user/session lock boundary. Account-status JSON uses the same canonical strings as HTTP profile responses. Failure codes and correlation-only logs avoid leaking exception text or account data. Cancellation and disconnect release the subscription slot.

The server reads committed events every second and sends changed pages, initial snapshots and twenty-second heartbeats. This uses the same durable PostgreSQL event log; no broker, new datastore or broader Worker grant is introduced. Reconnect resumes the accepted cursor. The browser validates subject, envelope, contiguous cursor and event IDs before advancing; old connection generations and callbacks after disposal are fenced. It coalesces invalidations into the existing authoritative HTTP recovery instead of overwriting drafts from socket data. Invalid pages or unavailable transport trigger bounded HTTP recovery and capped reconnect backoff. Profile polling, focus/online recovery and the mutation epoch remain active, including while reconnecting.

Tests cover websocket delivery and logout closure, origin denial, invalid cursors, one-subscription limits/cancellation, reconnect cursor, stale generation, cross-subject denial and startup-failure/disposal. The account browser scenario requires an actual SignalR snapshot and profile-update frame before checking profile event replay and automatic two-client recovery. Durable identity mutation retry keys and the remaining invitation/suspension/lifecycle requirements remain separate work.
