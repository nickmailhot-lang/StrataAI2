# Release bundle integrity and tested SBOMs — ARCH-11-FR-075/077/078/080/083

The release job now downloads both the exact image artifact and its tested security evidence from the current workflow run. Before assembly, the [release verifier](../../scripts/ci/verify-release-artifacts.py) checks complete checksum coverage, payload hashes, canonical repository/SHA/run/version identity, identical original image/security metadata bytes, nonempty image archives, and the three CycloneDX container inventories tagged with that same source SHA. The metrics receiver inventory is also required. These are integrity and identity checks; they do not replace image loading, runtime tests, vulnerability scans, or complete CycloneDX schema validation.

The security job binds its retained metadata/SBOM files with `SHA256SUMS` before its always-run evidence upload. A partial evidence artifact after scan failure remains diagnostic; the stable gate prevents it from reaching release assembly. Neither security nor release rebuilds application images.

Assembly copies the original tested SBOMs into `sbom/` and preserves the complete original security evidence under `security/`. The root checksum manifest includes the nested security manifest. Verification then requires all runtime/configuration/migration/inventory files and rejects missing environment examples, changed or mismatched SBOM copies, empty archives, incomplete/duplicate/traversing checksum entries, symlinks and unexpected hidden files. Missing/corrupt required payloads stop upload.

The bundle uploader explicitly includes hidden files only for the validated `bundle/` directory, where `.env.release.example` is the sole permitted hidden file. Previously, the job copied that example locally but the uploader's default excluded it. GitHub documents [hidden-file exclusion](https://github.com/actions/upload-artifact#uploading-hidden-files) and [permission loss in ZIP artifacts](https://github.com/actions/upload-artifact#limitations). The run guide now verifies checksums and restores executable permissions before running the four scripts. It starts PostgreSQL first, applies migrations and provisions restricted roles, then starts/waits for the application hosts; their readiness requires those prerequisites. Bundled architecture links point at the exact source commit rather than missing relative files.

The former bundle step only created an empty `sbom/` directory, never downloaded the tested SBOMs, and did not verify downloaded image checksums before copying them. The repaired source addresses these concrete omissions; current hosted release output is still required.

Validation: 45 workflow coverage/mutation checks and 13 release-verifier tests pass. Negative cases cover corrupted images, missing/wrong-commit SBOMs, different security run identity, missing environment examples, unexpected hidden secrets, changed inventory copies, invalid/duplicate/traversing checksum entries, extra unlisted files, empty images and safe CLI failure output. Actionlint validates workflow syntax/expressions.

An isolated Linux fixture executes the actual security checksum, release-input verification, bundle assembly and final verification commands successfully. It uses synthetic archive bytes and explicitly synthesized proof metadata, with the real retained historical `cef54e18` SBOMs to check compatibility with Trivy's emitted documents. Original SBOM/example bytes are preserved and architecture links are resolved. This does not demonstrate Docker-loadable images, current candidate provenance, startup on a clean Docker host, or full acceptance. The invocation-owned container is removed and existing services/volumes are preserved. Those runtime/release acceptance requirements remain open.

## Original image evidence through final copying

A new regression exposes a real weakness in the first bundle verifier: changing a copied image and recalculating the outer bundle hashes still passes. Those hashes describe the copied files but do not establish equality with the tested input. The failing regression reproduces this before the repair.

The bundle now retains the original image artifact's `SHA256SUMS` and canonical metadata under `images/`, in addition to the original security evidence. Final verification checks both nested manifests, requires identical root/image/security identity, and compares the retained image/security manifest and metadata bytes against the independently verified original input directories. Replacing an inner manifest to describe altered files therefore still fails CI's original-input comparison. This preserves the tested archive bytes across copying without an image rebuild.

All 18 release verifier cases pass on Windows and isolated Linux. New cases reject a changed image with recalculated outer hashes, replaced inner/outer image manifests, changed security evidence, and divergent copied image identity; matching original inputs pass. All 47 workflow coverage/mutation checks pass, including omission of original image evidence or final input comparison. Actionlint passes.

A separate isolated Linux fixture executes the actual updated checksum/input/assembly/final verification commands. Its positive assembly passes; changing the copied API archive and recalculating the outer hashes is refused, and recalculating both inner and outer manifests is also refused against the original inputs. Synthetic archive bytes/proof metadata and historical retained SBOMs remain explicit fixture limitations: this is copy/integrity evidence, not current Docker-loadable candidate or clean-host acceptance. Owned proof containers are removed, preserving existing services and volumes. Current hosted release verification remains required.
